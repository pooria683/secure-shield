# Deployment and operations

- Terminate TLS at a supported edge proxy, enforce the expected hostname and HTTPS, and set HSTS there after confirming your HTTPS rollout. Keep the Node listener private and block direct access; do not forward WebSocket upgrades or CONNECT to this gateway.
- Configure edge limits for connection count, body size, and header size, as well as idle and request timeouts. Apply per-client throttling at the edge using a trusted client identity. Secure Shield ignores forwarding headers and therefore sees a reverse proxy as one peer. **Before exposing the service**, tune peer and login limits for that topology, or set `rateLimit: false` if equivalent edge and app limits are in place. Do not disable throttling without a replacement. Counters reset on process restarts and are not shared across replicas; fixed windows can allow bursts near a boundary.
- Serve only intended public artifacts from a dedicated read-only deployment directory. Do not put credentials, user uploads, server code, or private documents there. Do not permit untrusted users to modify the directory, its ancestors, or its files: filesystem containment assumes a trusted immutable tree. Restart after switching releases. The static gateway supports root `index.html`, explicit filenames with a limited ASCII alphabet, a small media allowlist, and no directory listing or symlink aliases. Its restrictive CSP requires external same-origin scripts and styles rather than inline code.
- For applications, preserve safe-method semantics: no state changes via GET, HEAD or OPTIONS. Use anti-CSRF tokens and suitable cookie attributes in addition to the exact-origin check. Non-browser clients without Origin need an explicitly designed authentication and CSRF strategy; do not treat an Origin header as identity.
- Keep parser limits on actual received and decompressed bytes. If enabling upload routes, use a bounded upload parser, check file contents and types, generate safe filenames, quarantine outside the web root, scan as appropriate, and enforce authorization and quotas. Never build SQL, paths, HTML or include destinations by concatenating untrusted input.
- In staging, test legitimate routes, upload behavior, proxy limits and every state-changing client. Monitor block reasons, tune narrow settings, and have a rollback plan. Supervise the service with restart and shutdown deadlines and monitor errors separately from block events.
